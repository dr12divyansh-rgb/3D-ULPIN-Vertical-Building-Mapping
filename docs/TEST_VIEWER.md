# Temporary HTML Integration Test Viewer

A small, local-only web viewer to inspect one or more existing synthetic
buildings and their current Step 1/2/3 outputs.

> **SYNTHETIC PROTOTYPE DATA — Not cadastral / legal survey data.**
> This is a *test/demo* viewer. It is not the final city-scale viewer and it
> does not pretend the cadastral system is complete.

## What it shows

For a selected building:

| Layer | Source | Meaning |
|---|---|---|
| **LOD1** | `scene/lod1/building_XXXXXX.obj` | simple flat-top footprint extrusion (blue wireframe) |
| **Ground Truth LOD2** | `scene/ground_truth/lod2/building_XXXXXX.obj` | detailed external geometry, surfaces colored by type (wall / roof / ground) |
| **LiDAR** | `scene/lidar/pointcloud.ply` | synthetic LiDAR points colored by semantic class |
| **AI Prediction** | `ml/results/<exp>/predictions/<scene>/prediction.ply` | PointNet++ predicted classes |
| **Metadata** | `scene/ground_truth/building.json` | actual recorded building parameters |
| **ML metrics** | `ml/results/<exp>/per_building_metrics.json` | actual stored building precision/recall/F1/IoU |

LOD2 reconstruction (Step 4) does not exist yet and is explicitly marked
"not implemented" in the comparison panel — no fake reconstruction is shown.

## Start the viewer

The viewer must be served from the **project root** so the data paths work:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000/viewer/
```

Directly open a specific building (e.g. the unseen test scene):

```text
http://localhost:8000/viewer/?scene=scene_00005&building=40001
```

Optional query presets: `lidar=1`, `pred=1`, `overlay=1`, `context=1`,
`lod1=0`, `lod2=0`, `floor=2`.

## Rebuild the index

The viewer discovers scenes/buildings from `viewer/data/index.json`, which is
generated from the existing dataset metadata. Re-run it after regenerating the
dataset:

```bash
python viewer/build_index.py
```

`build_index.py` only *indexes* existing files; it never modifies the dataset
or the ML pipeline.

## Controls

- **Scene / Building** dropdowns, plus **◀ Prev / Next ▶**.
- **LOD1**, **Ground Truth LOD2**, **LiDAR**, **AI Prediction** checkboxes.
- **Overlay** — when enabled, checked layers are shown together; when
  disabled, only the first checked layer is shown.
- **Whole scene context** — show all points instead of only the selected
  building's points.
- **Point size** slider (LiDAR / prediction points).
- **Synthetic floor level** buttons — `All` or `Floor 1..N` (from the stored
  `floor_levels`); selecting a floor clips the view at that level and reports
  its Z range. This is a *synthetic floor level*, not an interior floor plan.
- **Reset camera**.

Orbit = left-drag · Pan = right-drag · Zoom = wheel.

## Data source

Everything comes from the existing repository outputs:

- Dataset: `ml/data/synthetic/{train,validation,test}/scene_XXXXX/`
- Predictions/metrics: `ml/results/experiment_*/`
- Ground-truth labels are generated by the Blender pipeline (Step 1/2);
  predictions come from the PointNet++ model (Step 3). Neither is altered by
  the viewer.

## How it works

- `viewer/src/loader.js` — dependency-free binary PLY parser + OBJ parser
  (the PLY parser is generic over the property list, so it handles both the
  LiDAR PLY and the prediction PLY).
- `viewer/src/scene.js` — Three.js mesh/point building, camera fitting, floor
  clipping.
- `viewer/src/controls.js` — selectors, next/prev, floor buttons.
- `viewer/src/metadata.js` — building info + ML info panels.
- `viewer/src/app.js` — orchestration.
- `viewer/vendor/` — locally vendored Three.js (r160 module build) and
  OrbitControls, so the viewer works fully offline (no CDN).

Prediction points share the exact point order with the LiDAR PLY, so the
viewer uses the LiDAR `building_id` column to filter **both** clouds to the
selected building without modifying coordinates.

## Limitations

- Test viewer only; no backend, no spatial database, no Cesium.
- Point clouds are loaded client-side (full scene ~12 MB LiDAR + ~10 MB
  prediction); fine for local use, not a city-scale solution.
- Training scenes have no stored prediction, so their ML panel says
  "AI prediction not available for this scene."
- Rare classes (vehicle/other) have near-zero metrics (see
  `docs/ML_SEGMENTATION.md`).
